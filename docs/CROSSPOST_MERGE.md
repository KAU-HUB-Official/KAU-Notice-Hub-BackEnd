# 교차 게시 합치기 판정

여러 게시판에 같은 내용이 올라온 공지를 하나로 합칠지 정하는 기준과, 실험으로 기각한 접근을 남긴다.
연구 데이터(`data/research/`)는 학번·성명이 섞여 있어 저장소에 올리지 않으므로, 판단 근거는 이 문서에 남긴다.

## 질문 정의

"두 공지가 같은 공지인가"가 아니라 **"두 공지를 하나로 묶어 본문 하나만 남겨도 읽는 대상자에게 지장이 없는가"** 로 묻는다(2026-09-15 결정).

- `merge`: 한쪽 본문만 남겨도 되거나, 대상마다 다른 부분(학과별 연락처·제출처·마감일 등)을 한 공지에 함께 적으면 되는 경우.
- `keep_both`: 합치기 어렵거나, 합치면 헷갈리거나 정보가 빠지는 경우. 둘 다 남기는 것도 정답이다.

## 판정 파이프라인 (2026-09-20 고정)

`scripts/research/classify_crosspost_pairs.py`가 순서대로 확인하고, 규칙은 `scripts/research/crosspost_rules.py`에 있다.

1. **후보**: 게시판이 다르고, 게시일 차이 7일 이내이며, 괄호 머리말을 뗀 제목이 같거나 글자 2-gram 유사도 0.8 이상.
2. **첨부파일 규칙**
   - 첨부파일이 전부 같고 개수도 같으면 합친다.
   - 두 공지 모두 첨부가 있는데 파일이 다르면 **다른 공지로 보고 둘 다 남긴다**(2026-09-19). 같은 시리즈라도 첨부가 다르면 주로 제공하는 정보가 다르기 때문이다. 한쪽에만 첨부가 있으면 적용하지 않는다(파일을 안 붙이고 옮긴 경우가 많다).
   - 같은 파일인지는 이름으로 본다. 공백·대소문자, 앞 번호(첨부1., 붙임2.), 확장자, 끝 표기((최종), (1)), 이름 안의 기호는 무시하고, 같은 문서가 PDF·한글로 함께 올라온 경우는 한 파일로 센다. `imageSrc.do` 같은 파일명이 아닌 값은 비교에서 뺀다.
   - 첨부가 다르면 본문이 같아도 다른 공지로 본다.
3. **본문 같음**: 정규화한 본문 글자가 정확히 같고(50자 이상) 본문 이미지도 같으면(둘 다 없거나 파일이 전부 같음) 합친다. 비슷한 정도(유사도)로는 판정하지 않는다. 글이 같아도 포스터만 다를 수 있어 한쪽에만 이미지가 있으면 적용하지 않는다.
4. **본문 이미지 규칙**: 본문 이미지 파일(sha256)이 전부 같고 개수도 같으면 합친다. 해시는 2단계까지 정하지 못한 쌍의 이미지만 구한다.
5. **나머지(판정 필요)**: LLM이 판정한다(`scripts/research/judge_merge_llm.py`, `PIPELINE_VERSION = "2026-09-20"`).
   1. **판정**: 두 공지의 본문만 넘긴다(게시판·게시일·제목·첨부 이름은 넘기지 않는다). merge면 기준 본문(A 또는 B)과 덧붙일 정보(다른 공지의 문장 그대로)를 받는다.
      - **한쪽에만 첨부가 있으면 기준 본문을 첨부 있는 쪽으로 고정한다**(2026-09-20). 내용이 같으면 첨부 있는 쪽만 남고, 다르면 둘 다 남는다. LLM 입력 맨 앞에 `기준 본문: A`처럼 알려주고, 응답의 기준 본문도 그 본문이나 none만 고를 수 있게 막는다. 첨부 이름은 넘기지 않는다.
   2. **합치기(코드)**: 기준 본문은 원문 그대로 두고, 덧붙일 정보가 있으면 끝에 `[추가 안내]`로 붙인다. LLM이 본문을 새로 쓰지 않는다.
   3. **검사**: 버려지는 쪽 공지에 적힌 정보 중 합친 공지에 없거나 다르게 적힌 것을 LLM이 나열한다.
   4. **최종**: 판정이 merge이고, 기준 본문이 있고, 검사에서 빠진 정보가 없을 때만 합친다. 그 밖에는 모두 둘 다 남긴다. **애매하면 나눈다.** 둘 다 남기는 것도 정답이므로, 잘못 합친 경우만 위험한 오류로 본다.
   - 모델: gpt-4.1-mini, temperature 0, 본문 최대 6,000자. 판정 1회에 merge인 쌍만 검사 1회를 더 부른다.

2026-09-19 기준 3년치(2023-01-01~) 공지 7,857건에서 후보 2,493쌍: 첨부 일치 599, 첨부 다름 219, 본문 같음 562, 본문 이미지 274, **판정 필요 839**(본문 유사도 0.9 이상 327, 0.6~0.9 193, 0.3~0.6 157, 0.3 미만 160, 비교 불가 2. 유사도는 기록용이며 판정에 쓰지 않는다).

### 판정 지시문

```
두 대학 공지의 본문 A, B를 비교해, 둘을 하나의 공지로 합쳐도 되는지 정한다.
합친다는 것은 한쪽 본문을 기준으로 남기고, 다른 공지에만 있는 정보를 덧붙이는 것이다.
두 공지에서 서로 다른 부분이 무엇인지를 보고 판단한다.

merge: 서로 다른 부분이 없거나, 다른 정보가 문의처·제출처·담당자·신청 링크 같은 단일 연락·접수 정보뿐이다.
  이런 정보는 합친 공지에 나란히 적으면 된다. 예: "기계공학전공 문의 …, 항공MRO전공 문의 …"
  한쪽이 다른 쪽 내용을 모두 담고 더 자세할 뿐이면 다른 부분이 아니다. 더 자세한 쪽을 기준으로 남긴다.
keep_both: 일정·장소·자격·조건·절차·금액·과목·선발 인원처럼 공지의 핵심 내용이 서로 다르다.
  이런 공지를 합치면 한 공지를 보던 사람이 자기와 관계없는 내용을 읽어야 하거나,
  어느 내용이 자기에게 해당하는지 헷갈린다.

애매하면 keep_both로 한다. merge는 합쳐도 지장이 없다고 확신할 때만 고른다.

merge이면 기준 본문(A 또는 B)과 덧붙일 정보를 적는다. 입력에 기준 본문이 정해져 있으면 그 본문을 기준으로 한다.
덧붙일 정보는 다른 공지의 문장을 그대로 옮기고, 요약하거나 새 문장을 쓰지 않는다. 본문에 없는 내용은 만들지 않는다.
```

입력: `[공지 A 본문]`, `[공지 B 본문]`. 한쪽에만 첨부가 있으면 맨 앞에 `기준 본문: A`(또는 B)를 붙인다.

출력: `judgment`(merge/keep_both), `reason`(한 문장), `base`(A/B/none. 기준 본문이 고정되면 그 본문/none), `additions`(덧붙일 문장 목록).

### 검사 지시문

```
원래 공지와 합친 공지를 비교한다.
원래 공지에 적혀 있는 정보(일정·장소·대상·자격·신청 방법·제출처·문의처·금액 등) 가운데
합친 공지에 없거나 다르게 적힌 것만 나열한다.
원래 공지에 없는 항목, 합친 공지에만 있는 정보, 표현만 다르고 뜻이 같은 것은 넣지 않는다. 없으면 빈 목록이다.
```

입력은 `[원래 공지]`(버려지는 쪽 본문)와 `[합친 공지]`, 출력은 `missing`(빠진 정보 목록)이다.

### 합친 공지 모양

```
(기준 공지 본문 그대로)

[추가 안내]
- (다른 공지에서 옮긴 문장)
```

### 평가 지표

- **잘못 합침**: 라벨이 keep_both인데 최종 merge한 쌍 수. 0에 가까워야 한다.
- **합친 비율**: 라벨이 merge인 쌍 중 최종 merge한 비율. 중복을 얼마나 줄이는지 보여준다.
- 일치율 하나로 보지 않는다. 라벨이 merge로 크게 기울어 전부 merge라고만 해도 일치율이 높게 나온다.

## LLM 평가 결과 (2026-09-20)

표본 250쌍 중 규칙으로 정해지지 않는 **186쌍**을 고정된 파이프라인으로 판정했다(gpt-4.1-mini, 판정 186회 + 검사 149회, $0.29).

| 지표 | 값 |
|---|---|
| 잘못 합침 (라벨 keep_both → 최종 merge) | **3 / 26 (12%)**, 전체 186쌍 기준 1.6% |
| 둘 다 남긴 비율 (라벨 keep_both 중) | 23 / 26 (88%) |
| 합친 비율 (라벨 merge 중) | **74 / 160 (46%)** |
| 판정 단계만 볼 때 라벨 일치 | 84% |
| 검사에서 merge → keep_both 로 뒤집힘 | 149쌍 중 72쌍 |

- **잘못 합친 3쌍은 모두 "한쪽이 다른 쪽을 모두 담고 더 자세하다"는 문장을 적용한 경우다.** 학과별 수강신청 안내 2쌍과 동계 단축근무 1쌍으로, 더 자세한 쪽에 다른 학과·다른 기간 내용이 들어 있어 사람은 둘 다 남기라고 봤다.
- **검사가 합치기를 절반 가까이 막는다.** 막은 이유는 대체로 실제 차이다(문의처 번호 02-300-0028 ↔ 0078, 신청 마감 10.17 ↔ 10.20, 장학금 총액과 선발 기준 누락). 다만 "합친 공지에만 있는 정보"를 빠졌다고 적는 오탐도 섞인다. 오탐은 결과를 둘 다 남기는 쪽으로만 바꾼다.
- 애매하면 나누는 원칙의 대가로 합치는 양이 줄었다. 3년치 839쌍에 적용하면 약 370쌍이 합쳐지고 나머지는 둘 다 남는다는 뜻이다.

데이터와 결과는 `data/research/frozen_2026-09-20.json`에 파일 해시·건수·파이프라인 버전·커밋으로 고정했다(`scripts/research/freeze_dataset.py`).

## 실험으로 기각한 접근

| 접근 | 기각 이유 |
|---|---|
| 제목이 같고 7일 이내면 바로 한 그룹으로 묶기 | 학부와 대학원 공지가 한 공지로 합쳐졌다. 2025-2 수강신청은 일반대학원 공지가 9일 늦게 올라와 대상이 다른데도 제목이 같아 묶였다. |
| 본문 유사도 임계값만으로 자동 분리 | 같은 공지를 옮겨 적으면서 문장을 바꾼 경우와, 대상만 다른 변형 공지를 가르지 못했다. 임계값을 낮추면 대상이 다른 공지가 합쳐지고, 높이면 같은 공지가 갈라졌다. |
| 첨부파일 이름이 하나라도 겹치면 합치기 | 같은 신청 양식을 쓰는 다른 공지까지 합쳐졌다. 이름·개수가 전부 같을 때만 적용하도록 좁혔다(2026-09-15). |
| 첨부 이름을 글자 그대로 비교 | 같은 공고의 PDF·한글 파일, 번호만 밀린 `첨부1.`·`첨부2.`, 밑줄만 다른 이름이 다른 파일로 잡혔다. 표본에서 이런 7쌍은 모두 합쳐도 되는 공지였다. 표기를 걷어내고 비교한다(2026-09-19). |
| 한쪽에만 첨부가 있어도 다른 공지로 보기 | 한 게시판이 파일을 안 붙이고 본문만 옮긴 경우가 많다. 표본 55쌍 중 45쌍이 합쳐도 되는 공지였다(2026-09-19). |
| 본문 이미지 **주소**로 겹침 판정 | 게시판마다 포스터를 새로 올려 주소가 달라진다. 판정 필요 구간에서 주소가 겹친 쌍은 31쌍인데 파일 내용이 같은 쌍은 170쌍이었다. 파일 해시 비교로 바꿨다. |
| 본문 이미지가 하나라도 겹치면 합치기 | 학과 로고·공통 배너를 함께 쓰는 다른 공지가 합쳐질 수 있다. 이미지가 전부 같을 때만 적용한다. |
| LLM 지시문 v1~v3 | "같은 공지인가"로 묻고 보충 자료 카테고리와 "명시 없음" 규칙을 두었더니 대상이 다른 공지를 합쳤다. 지시문도 길었다. 본문만 넘기고 합쳐도 되는지 묻는 v4로 바꿨다. |
| 본문 유사도 0.9 이상이면 자동 합침 | 판정 필요 쌍을 셀 때 들어간 가정이 승인 없이 파이프라인에 들어갔다. 유사도로는 재게시와 대상별 변형 공지를 가를 수 없다. 글자가 완전히 같고 본문 이미지도 같을 때만 합친다(2026-09-19). |
| LLM이 항목을 뽑고 코드가 판정(v4) | 같은 주제·대상 관계·모순되는 사실을 뽑게 한 뒤 코드가 정했다. 질문이 "같은 공지인가"라 합치기 기준과 맞지 않았다. LLM이 합쳐도 되는지 직접 정하게 바꿨다(2026-09-19). |
| "대상이 다르면 keep_both" 문구 | "대상마다 다른 문의처를 덧붙이면 merge"와 충돌했다(학과별로 문의처만 다른 공지). 기준을 "두 공지에서 무엇이 다른가"로 바꿨다(2026-09-19). |
| 합칠 수 있다는 판정을 그대로 믿기 | 판정 LLM이 덧붙일 정보를 일부만 옮겨(강좌표의 수강 신청 기간 열 등) 합친 본문에서 정보가 빠졌다. 실제로 합친 본문을 만들어 빠진 정보를 따로 검사한다(2026-09-19). |
| 덧붙일 정보를 LLM이 요약해 쓰기 | "※ 추가 정보는 확인 필요합니다" 같은 원문에 없는 문장이 들어갔다. 다른 공지의 문장을 그대로 옮기게 했다(2026-09-19). |
| 게시판·게시일·제목·첨부 목록을 LLM에 함께 넘기기 | 메타데이터가 노이즈가 됐다. 판정은 본문만 보고 한다. |
| Markdown 라벨링 양식 | 미리보기로 보면 수정이 안 되고, 편집기로 열면 읽기 나쁘다. 클릭으로 체크하고 JSON으로 내보내는 HTML 페이지로 바꿨다. |

관련 기각 사항: 오픈웨이트 모델 자체 서빙(2026-09-14), RAGAS `answer_relevancy` 지표(`docs/RAG_EVALUATION.md`).

## 라벨 상태 (2026-09-19)

판정 필요 구간에서 표본 200쌍을 뽑아 라벨을 정했다(`scripts/research/finalize_judgment_labels.py`).

- Claude가 본문만 보고 200쌍을 판정했다. 확신 낮은 38쌍과 확신 높은 쌍 중 무작위 10쌍(대조)을 팀원 4명이 각자 라벨링했다.
- 팀원 답이 모두 같은 30쌍은 그 답을, 엇갈린 18쌍은 최종 판정자(박성진)의 답을 쓴다. 나머지 152쌍은 Claude 판정을 쓴다.
- 최종 판정자가 모르겠음을 고른 4쌍은 라벨이 없다. 3쌍은 대상별 문의처·교수 목록을 한 공지에 합칠 수 있는지에 달려 있어, LLM이 본문을 합쳐 쓰는 설계의 시험 사례로 남긴다.
- 대조 10쌍 중 9쌍에서 사람 라벨과 Claude 판정이 같았다. 팀원끼리 두 명씩 비교한 kappa는 0.29~0.74다.
- 첨부 다름 규칙을 넣은 뒤 표본 200쌍 중 64쌍은 규칙으로 정해지고 136쌍이 판정 필요로 남는다(라벨 있는 135쌍으로 LLM을 평가한다).
- 표본은 본문 유사도 0.9 미만 구간에서만 뽑았다. 본문 같음 규칙으로 바꾸며 판정 필요에 새로 들어온 0.9 이상 327쌍은 평가 표본에 없다.

## 아직 정하지 않은 것

- 첨부파일 규칙이 합치라고 한 6쌍 중 3쌍에서 Claude는 `keep_both`로 봤다(2024 예비군훈련, 2025-1 연구계획서, 2025-2 코드쉐어 개설과목). 예외를 둘지 정하지 않았다.
- 후속 공지가 같은 포스터를 쓰는 경우(학과설명회 자료 업데이트, 교육 조기 마감안내)는 합치되 나중 공지의 본문을 남겨야 한다. 남길 본문을 고르는 규칙은 아직 없다.
- 검사 단계에 오탐이 섞인다(합친 공지에만 있는 정보를 빠졌다고 하는 등). 결과를 둘 다 남기는 쪽으로만 바꾸므로 지금 원칙에서는 안전한 쪽 오류다.

## college 게시판 본문 이미지 버그 (2026-09-15 발견, 2026-09-16 조치)

`college.kau.ac.kr` 상세 API는 이전 글·다음 글의 본문 HTML(`resultPre`/`resultPost`)을 함께 준다. 크롤러가 응답 전체에서 본문 이미지를 뽑아 **이웃 글의 이미지가 공지에 붙었다.** 이미지가 있는 college 공지 1,507건 중 1,267건이 영향을 받았고, 한 K-MOOC 포스터가 서로 무관한 공지 48건에 들어가 있었다.

- 조치: 파서가 그 글의 `nttCn`만 돌려주고 크롤러가 거기서만 이미지를 찾게 고쳤다(`BaseParser.body_html`). 회귀 테스트는 `tests/test_board_crawler.py::test_college_body_images_ignore_previous_and_next_articles`.
- 연구 데이터: college 공지 2,736건의 상세를 다시 받아(`scripts/research/refetch_college_details.py`) 이미지 목록 1,291건을 고치고 딸려온 이미지 2,042개를 뺐다.
- 보강: 이웃 글 이미지로 본문이 생성됐던 105건을 다시 보강했다(gpt-4.1-mini 116회, 약 $0.14). 96건은 본문을 새로 만들었고, 9건은 원래 이미지가 없어졌거나(404) BMP라 복구하지 못해 제외 대상이 됐다.
- 운영 서버에서 이미지 보강을 켠 적이 있다면 college 공지 본문이 같은 이유로 잘못 생성됐을 수 있다. 확인하지 않았다.
