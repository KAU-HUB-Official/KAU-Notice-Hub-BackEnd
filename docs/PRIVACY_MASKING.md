# 개인 식별자 마스킹

공지의 **학번과 사람 이름**을 본문, 검색 인덱스, LLM 입력 세 곳에서 가린다.

| 대상 | 방식 | 결과 |
| --- | --- | --- |
| 10자리 학번 | 정규식 (`app/privacy.py`) | `2017999928` → `2017○○○○28` |
| 사람 이름 (학생·교수·담당자 모두) | NER 모델 (`app/name_masking.py`) | `홍길동` → `홍○○` |

전화번호(휴대폰 포함), 이메일, 계좌번호는 가리지 않는다. 아래 "연락처 기준" 참고.

## 목적

원문은 이미 학교 사이트에 공개되어 있다. 문제는 우리가 성격을 바꾼 부분이다.
학교는 공지를 68개 게시판에 나눠 올리고 시간이 지나면 묻히지만, 우리는 3년치를
한 곳에 모아 학번과 이름을 전문 검색 대상으로 만들었다. 실제로 학번 하나를
검색하면 서로 다른 두 공지가 이어져, 한 학생이 특정 교육 수강자이면서 특정 학기
졸업사정 대상자라는 사실이 한 번에 드러났다.

검색 경로를 막는 것이 1차 목적이고, 유출 위험을 줄이기 위해 본문 표시까지 함께
가린다.

## 적용 지점

| 위치 | 대상 |
| --- | --- |
| `app/normalize.py` `normalize_notice()` | 사용자에게 렌더되는 공지 본문 (`mask_notice_body()`) |
| `app/search.py` `build_search_text()` | 검색 인덱스. SQLite 적재(`app/ingest.py`)와 JSON 폴백 검색이 함께 쓰는 단일 관문이다 |
| `app/chat_service.py` `build_context()` | RAG 답변 컨텍스트 |
| `app/chat_service.py` `build_rerank_list()` | rerank 입력 |
| `app/chat_service.py` `fallback_answer()` | LLM 미사용 시 노출되는 발췌 |

모두 `mask_personal_identifiers()`를 거친다. 학번을 먼저 가리고 이름을 가린다.

### 건드리지 않는 것

- **제목**: 원문 URL이 없는 공지는 `build_notice_id()`가 제목으로 ID를 만든다.
  제목을 바꾸면 그 공지의 ID가 변해 사용자가 저장한 북마크가 끊긴다.
- **첨부파일**: 파일명과 URL을 그대로 둔다. PDF·HWP·이미지 안의 명단은 텍스트
  마스킹이 닿지 않으므로 여전히 노출된다.

## 학번

10자리 학번은 앞 4자리(입학년도)와 뒤 2자리만 남긴다. 학교도 `2025****40` 형태로
같은 관례를 쓴다.

- **예시 학번도 가린다.** 숫자만 보고는 `2026123456` 같은 예시와 실제 학번을 구분할
  수 없고, 실제 학번이 우연히 예시처럼 생겼으면 그대로 노출된다.
- 앞뒤가 숫자·하이픈·점이면 학번으로 보지 않는다. 전화번호와 파일명 날짜
  (`명단(20240614).pdf`)를 학번으로 오인하지 않기 위해서다.

## 이름

### 모델

`atonlee/koelectra-ko-pii-ner`(KoELECTRA-small, Apache-2.0, 커밋 `1e75c01e`)를 검수한
공지 478건(1차 279건 + 2차 199건)으로 파인튜닝하고 오닉스 int8로 바꾼 파일을 쓴다.
실명이 든 공지로 학습해서 학습 문장을 일부 외울 수 있으므로 저장소에 올리지
않고 서버에만 둔다.
서버에서는 PyTorch 없이 `onnxruntime`과 `tokenizers`만으로 돈다.

모델 결과에서 세 가지만 거른다. 그 밖의 이름 판단 규칙(단어 목록, 길이 조건, 직함
예외 등)은 덧붙이지 않는다.

- **신뢰 점수 0.5 미만은 가리지 않는다** (`MIN_SCORE`). 구간 신뢰 점수는 구간 토큰 확률의 평균이다.
- **한글이 없는 구간은 가리지 않는다.** 해외 대학·시험 이름(`San Bernardino`,
  `Duolingo`)이 가려져 교환학생 공지의 핵심 정보와 검색이 사라졌다. 표본에서 영문으로만
  된 이름은 외국 정상 1명뿐이었다.
- **URL과 겹치는 구간은 가리지 않는다.** 모델 입력에서 URL을 공백으로 지우므로
  `**[종](https://forms.gle/…)료**`처럼 링크 앞뒤 글자가 한 구간으로 잡히면 그 사이 URL까지
  가려져 링크가 깨졌다(전수 점검에서 1건).

모델 입력에서 URL과 마크다운 기호만 같은 길이의 공백으로 바꾼다. URL 안을 가리면
링크가 깨지기 때문이다. 가릴 때는 글자와 숫자만 `○`로 바꾸고, 구간 안의 공백과
마크다운 기호(`**` 등)는 그대로 둔다. 학습할 때도 같은 방식으로 입력을 만들었다.

### 모델 선택

두 한국어 NER 모델을 같은 공지 표본으로 비교했다. 무작위 공지 250건과 학번·성명
표가 있는 공지를 합친 279건에서, 두 모델과 이전 이름 규칙이 찾은 후보 992개를
판정했다(Claude가 판정하고 사람이 검수). 실제 이름은 362개였다(그중 227개가 캡스톤
공지 한 건). 아래 표는 거르기 전 모델 결과다.

| 모델 | 이름 전부 가림 | 일부만 가림 | 놓침 | 찾은 구간 중 이름 아님 |
| --- | --- | --- | --- | --- |
| **`atonlee/koelectra-ko-pii-ner`** (채택) | **95.9%** | 4 | 11 | 51.5% |
| `Leo97/KoELECTRA-small-v3-modu-ner` | 57.2% | 63 | 92 | 9.9% |
| 채택 모델 오닉스 int8 | 95.3% | 3 | 14 | 51.0% |

- 채택 모델은 이름을 거의 다 찾지만, 찾은 구간의 절반은 이름이 아니다. 대부분
  `장 소`, `문 의`, `대 상` 같은 띄어 쓴 양식 항목명, `은상`, `엄수`, 해외 대학 이름이다.
- 다른 모델은 정확하지만 이름의 40% 이상을 놓치거나 `장○혁`처럼 일부만 가렸다.
- **이름이 새는 것보다 단어가 더 가려지는 쪽을 택했다.**

### 파인튜닝 전 기준 점수 (원래 모델)

원래 모델은 앱 코드(오닉스 int8)에서 기준 0.8로 이름의 92.3%(334/362)를 전부 가렸지만,
가린 구간의 29.9%(134/448)가 이름이 아니었다. 대부분 `장 소`, `문 의` 같은 띄어 쓴 양식
항목명과 `은상`, `엄수`였다. 기준을 올리면 오탐보다 놓치는 이름이 더 빨리 늘어서(0.85에서
놓침 25 → 36개) 기준만으로는 오탐을 줄일 수 없었다.

### 1차 파인튜닝

판정한 후보 992개를 정답으로 원래 모델을 더 학습했다. 이름(name·part)은 이름으로, 이름이
아닌 구간은 `O`로 학습하고, 여러 이름이 한 구간으로 묶인 multi 후보는 경계를 몰라 뺐다.
학습 설정은 3 epoch, learning rate 3e-5, batch 8이다(`ner_eval/finetune.py`).

같은 공지로 학습하고 평가하면 점수가 부풀려지므로 **공지 단위 5겹 교차 검증**으로 쟀다.
공지 279건을 다섯 묶음으로 나눠 네 묶음으로 학습하고 남은 묶음으로 평가하기를 다섯 번
반복해, 모든 공지를 학습에 쓰지 않은 상태로 한 번씩 평가했다. 원래 모델도 같은 공지로 쟀다.
아래는 PyTorch 결과이고, 한글이 있는 구간만 센다.

| 모델 | 기준 | 이름 전부 가림 | 가린 구간 중 이름 아님 |
| --- | --- | --- | --- |
| 원래 모델 | 0.8 | 91.2% (330/362) | 30.1% (135/449) |
| **파인튜닝** | **0.5** | **92.0% (333/362)** | **3.3% (12/359)** |

파인튜닝 모델의 기준별 결과:

| 기준 | 이름 전부 가림 | 이름 아님 |
| --- | --- | --- |
| **0.5** | **92.0%** | **3.3%** |
| 0.6 | 91.7% | 3.4% |
| 0.7 | 90.1% | 3.2% |
| 0.8 | 87.3% | 3.0% |
| 0.9 | 75.1% | 2.4% |

기준을 올려도 이름 아닌 구간은 거의 줄지 않고 놓치는 이름만 늘어서 0.5로 정했다.
오탐을 거르는 역할을 기준 점수 대신 모델이 하게 된 것이다.

1차 모델은 279건 전부로 한 번 더 학습해 배포했다.

- 이름 362개 중 227개가 캡스톤 명단 공지 한 건에 있어서, 이 공지가 어느 묶음에 들어가느냐에
  따라 숫자가 달라질 수 있다. 그래서 아래의 학습에 쓰지 않은 평가 공지로 다시 쟀다.
- 두 모델과 이전 규칙이 모두 놓친 이름은 후보에 없으므로 실제 재현율은 표보다 조금 낮을 수 있다.

### 2차 파인튜닝

1차 모델로 전체 공지를 가려 본 뒤, 1차 표본에 없는 공지 중 이름이 아닐 수 있는 구간이 하나라도
있는 공지 199건을 골라 가린 구간 1,146개를 전부 판정했다(이름 494, 이름 일부 20, 이름 아님 615,
여러 이름 17). 학습 코드는 표시하지 않은 글자를 모두 "이름 아님"으로 배우므로 고른 공지에서는
가린 구간을 빠짐없이 넣었다. 1차와 2차를 합친 478건으로 같은 설정(3 epoch, learning rate 3e-5,
batch 8)으로 다시 학습했다(`ner_eval/finetune.py final2`).

### 평가 공지

1차·2차 어디에도 쓰지 않은 공지 50건을 따로 떼어 정답을 직접 적었다. 모델이 이름을 하나라도
가린 공지 40건과 하나도 가리지 않은 공지 10건이다. 뒤의 10건은 모델이 통째로 놓친 이름을 찾기
위해 넣었다. 정답은 공지마다 적은 사람 이름 목록이고, 본문에서 그 이름이 나오는 157곳이 정답
구간이다. 모델 결과와 상관없이 정했으므로 어떤 모델이든 같은 기준으로 잴 수 있다. 이 공지는
앞으로 어떤 학습에도 넣지 않는다(`ner_eval/evaluate.py`).

앱 코드(오닉스 int8, 한글 구간만)로 잰 결과다. 오탐률은 가린 구간(두 글자 이상) 중 정답 이름과
겹치지 않는 비율이다.

| 모델 | 기준 | 이름 전부 가림 | 일부만 | 놓침 | 오탐 | 학교가 가린 이름 빼면 |
| --- | --- | --- | --- | --- | --- | --- |
| 1차 (279건) | 0.5 | 95.5% (150/157) | 2 | 5 | 21.2% (41/193) | 5.0% (8/160) |
| **2차 (478건, 배포)** | **0.5** | **96.8% (152/157)** | **0** | **5** | **1.3% (2/154)** | **1.3% (2/154)** |

- 1차 모델 오탐의 대부분은 학교가 이미 가린 이름(`김*진`)을 다시 가린 것이다. 읽는 데 지장은
  없지만 2차 검수에서 이름 아님으로 표시했고, 2차 모델은 이를 가리지 않는다.
- 2차 모델은 기준 0.5~0.8에서 오탐이 1.3%로 같고 놓치는 이름만 늘어서(0.8에서 전부 가림 93.6%)
  기준은 0.5를 그대로 쓴다.
- 2차 모델에서 새로 생긴 실수는 일반 단어와 같은 이름을 놓친 1건이다.

### 서버 자원

`python:3.13-slim` 컨테이너(메모리 750MiB, CPU 2개 제한)에서 잰 값이다.

| 항목 | 값 |
| --- | --- |
| 모델 파일 (`model_int8.onnx` + `tokenizer.json` + `config.json`) | 15.5MB |
| 도커 이미지 증가 (`onnxruntime`, `numpy`, `tokenizers`와 의존성) | 282MB → 526MB |
| 프로세스당 메모리 (런타임 import 약 30MiB + 모델 약 45MiB) | 약 75~90MiB |
| API 워커 2개가 챗봇 요청을 받은 뒤 컨테이너 메모리 | 173MiB → 299MiB |
| 전체 공지 7,857건 첫 적재 | 740초 (CPU 1스레드) |
| 이름 위치 캐시 (`name_mask_cache.db`) | 2.3MB |

모델은 처음 이름을 가릴 때 그 프로세스에 올라가므로, 챗봇·검색 요청을 받은 워커마다
하나씩 올라간다. 적재의 최고 메모리(공지 JSON 전체를 읽는 순간 약 665MiB)는 모델을
켜도 같았다. 모델이 JSON을 다 읽은 뒤에 올라가기 때문이다.

### 캐시

공지 DB는 크롤링마다 전체를 다시 적재한다. 그때마다 전체를 다시 돌리지 않도록,
본문 해시별로 찾은 이름 위치를 `NAME_MASK_CACHE_PATH`(compose에서는
`/data/name_mask_cache.db`)에 저장한다. 바뀌지 않은 본문은 모델을 다시 돌리지 않는다.
가린 결과도 "더 가릴 것 없음"으로 저장해, 검색 인덱스와 챗봇이 이미 가린 본문을
다시 넘겨도 모델을 또 돌리지 않는다. 캐시 키에는 모델 버전(`MODEL_VERSION`)이 들어가므로
모델을 바꾸면 이전 결과는 쓰이지 않는다. 캐시 파일은 지워도 다음 적재 때 다시 만들어진다.

### 모델 파일

```bash
python scripts/install_name_model.py name_audit/finetuned_v2/model   # 원본 폴더 → NAME_MODEL_DIR
python scripts/install_name_model.py --check                           # 들어 있는 파일 확인
```

`NAME_MODEL_DIR`(기본 `models/kau-name-ner`)에 넣는다. 평가한 파일과 SHA-256이 다르면
넣지 않는다(`MODEL_SHA256`). 모델 파일은 커밋하지 않는다(`.gitignore`). 서버에 넣는 방법은
[DEPLOYMENT.md](DEPLOYMENT.md#이름-마스킹-모델-준비)에 있다. **`PRIVACY_MASK_NAMES`가 켜져 있는데
모델 파일이 없으면 이름을 가리지 않고 넘어가는 대신 오류를 낸다.** 조용히 실명이 노출되는
것을 막기 위해서다.

## 설정

| 환경변수 | 기본 | 설명 |
| --- | --- | --- |
| `PRIVACY_MASK_BODY` | `true` | 끄면 본문만 원문으로 돌아간다. 검색 인덱스와 LLM 입력은 계속 가려진다 |
| `PRIVACY_MASK_NAMES` | `true` | 끄면 이름을 가리지 않는다. 학번은 계속 가린다 |
| `NAME_MODEL_DIR` | `./models/kau-name-ner` | 모델 파일 폴더 (compose: `/models/kau-name-ner`) |
| `NAME_MASK_CACHE_PATH` | `./data/name_mask_cache.db` | 이름 위치 캐시 (compose: `/data/name_mask_cache.db`) |

공지 DB는 크롤링마다 통째로 교체되므로 설정을 바꾸고 다음 적재를 기다리면 된다.

## 연락처 기준

전화번호(휴대폰 포함), 이메일, 계좌번호는 가리지 않는다. 전수 확인 결과 사실상
전부 부서 업무 연락처와 학교 법인계좌이고, 휴대폰도 대부분 외부 운영사무국
담당자다. 처음에는 전부 가렸지만 공지 상세에서 문의처를 읽을 수 없고 챗봇도
문의처를 답하지 못했다.

| 유형 | 전수 건수 |
| --- | --- |
| 일반 전화 | 4,620 |

주민등록번호와 생년월일은 따로 처리하지 않는다. 전수 스캔 0건이고, 학교가 공지에
올리지 않으며 올라오더라도 학교 쪽에서 가려서 게시한다.

## 마스킹 문자

`*`를 쓰지 않는다. 본문도 가리므로 마스킹 결과가 마크다운에 그대로 들어가는데,
공지는 굵게를 많이 써서 `*`가 섞이면 강조 파싱이 깨진다. `○`는 마크다운에서 의미가
없고, 학교가 이미 `박○영` 형태로 쓰는 글자라 표기도 일관된다.

## 남는 한계

- 원문은 학교 사이트에 그대로 공개되어 있다. 마스킹은 보호가 아니라 우리가
  증폭하지 않는다는 뜻이다.
- **명단 상당수는 첨부 PDF·HWP·이미지 안에 있다.** 제목에 `명단`·`합격자`·`선발자`가
  들어간 첨부파일이 150건이고, 우리는 다운로드 주소만 제공하므로 손을 댈 수 없다.
- 평가 공지에서 이름의 3.2%를 가리지 못했다(157곳 중 5곳). 가린 구간의 1.3%는 이름이
  아니라서 일부 단어가 가려지고, 가려진 단어로는 검색되지 않는다.
- 평가 공지는 50건이라 수치의 폭이 크다. 이름 한 곳이 1%포인트 가까이 움직인다.
- 영문으로만 쓴 이름은 가리지 않는다.
- 교수·담당자 이름도 가리므로, 공지에서 누구에게 문의할지는 이름 대신 부서와
  연락처로 찾아야 한다.

## 테스트와 전수 점검

| 위치 | 내용 |
| --- | --- |
| `tests/test_privacy.py` | 학번, 연락처를 남기는지, 본문·검색 인덱스·공지 ID |
| `tests/test_name_masking.py` | 이름 구간 처리, 캐시, 설정. 실제 모델 테스트(학번 뒤 `선발`·`예비`, 여러 행 표 머리글 등)는 모델 파일이 있을 때만 돈다 |
| `tests/test_privacy_pipeline.py` | JSON 적재 → 공지 목록·상세·검색 API, 챗봇 LLM 입력(`build_context`, `build_rerank_list`, `fallback_answer`)이 가려지는지 |

전체 공지를 실제로 가려 보고 점검하려면:

```bash
python scripts/audit_privacy_masking.py [공지 JSON] [--top N | --all]
```

남은 학번 수, 마스킹 전후로 바뀐 URL 수, 이름으로 가린 단어 목록을 출력한다. 앞의 두
값은 0이어야 하고, 단어 목록은 오탐이 섞였는지 사람이 훑어본다. 목록에 실명이 들어
있으므로 출력을 공유하지 않는다.
